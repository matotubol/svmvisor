15.31
SVM-Lock
The SVM-Lock feature allows software to prevent EFER.SVME from being set, either 
unconditionally or with a 64-bit key to re-enable SVM functionality. 
Support for SVM-Lock is indicated by CPUID Fn8000_000A_EDX[SVML] = 1. On processors that 
support the SVM-Lock feature, SKINIT and STGI can be executed even if EFER.SVME=0. See 
descriptions of LOCK and SVMDIS bits in Section 15.30.1. When the SVM-Lock feature is not 
available, hypervisors can use the read-only VM_CR.SVMDIS bit to detect SVM (see Section 15.4).
15.31.1  SVM_KEY MSR (C001_0118h)
The write-only SVM_KEY MSR is used to create a password-protected mechanism to clear 
VM_CR.LOCK. 
When VM_CR.LOCK is zero, writes to SVM_KEY MSR set the 64-bit SVM Key value. 
When VM_CR.LOCK is one, writes to SVM_KEY MSR compare the written value to the SVM Key 
value; if the values match and are non-zero, the VM_CR.LOCK bit is cleared. If the values mismatch 
or the SVM Key value is zero, the write to SVM_KEY is ignored, and VM_CR.LOCK is unmodified. 
Software should read VM_CR.LOCK after writing SVM_KEY to determine whether the unlock 
succeeded.
