OSPM may indicate support for multiple OS interface / behavior strings if the operating system supports the behaviors.
For example, a newer version of an operating system may indicate support for strings from all or some of the prior
versions of that operating system.
_OSI provides the platform with the ability to support new operating system versions and their associated features
when they become available. OSPM can choose to expose new functionality based on the _OSI argument string. That
is, OSPM can use the strings passed into _OSI to ensure compatibility between older platforms and newer operating
systems by maintaining known compatible behavior for a platform. As such, it is recommended that _OSI be evaluated
by the \_SB.INI control method so that platform compatible behavior or features are available early in operating system
initialization.
Since feature group functionality may be dependent on OSPM implementation, it may be required that OS vendor-
defined strings be checked before feature group strings.
Platform developers should consult OS vendor specific information for OS vendor defined strings representing a set of
OS interfaces and behaviors. ACPI defined strings representing an operating system and an ACPI feature group are
listed in the following tables.
